# SQL Parser

`sql.parse` 使用不会执行 SQL 的文本扫描器解析常见 `CREATE TABLE` 语句，提取表、字段、完整类型、长度/精度/小数位、可空性、默认值、主键、唯一、外键、自增、注释、分区表达式和解析警告。

```text
# 输出文件名使用本次任务 ID，例如 <task-id>.json
testbox run sql.parse --input ./schema.sql --format json

# CSV 输出为 <task-id>.csv
testbox run sql.parse --input ./schema.sql --format csv

# Excel 输出为 <task-id>.xlsx
testbox run sql.parse --input ./schema.sql --format xlsx
```

三种格式包含相同的字段清单和约束信息，只是文件载体不同。JSON 适合程序消费，CSV 适合文本处理和数据导入，Excel 工作簿名为“字段清单”，适合直接查看与交付。

支持 `json`、`csv` 和 `xlsx` 输出。`dialect` 默认为 `auto`，会根据 DDL 特征自动识别数据库类型；也可在 GUI 的“数据库类型”下拉框或 CLI 中明确指定 `mysql`、`postgresql`、`sqlserver`、`oracle`、`sqlite`、`hudi`、`hive`、`hbase`、`maxcompute` 或其别名 `mc`。显式选择始终优先于自动识别。通用 SQL 没有足够的方言特征时保留为 `auto`，仍按兼容语法解析。

执行结果的 `requested_dialect` 表示用户选择，`dialect` 表示实际采用的方言；输出字段清单中的 `dialect` 同样记录实际值。`include_constraints=false` 会从字段清单中移除主键、唯一键和外键列（默认保留），`fail_on_unsupported=true` 可在存在无法识别定义时直接失败。可在项目根目录 `config.yaml` 设置 `input_encoding: gb18030` 处理非 UTF-8 SQL 文件。

当前已通过自测的兼容范围包括：

- MySQL：反引号、`UNSIGNED`、`ENUM`、`AUTO_INCREMENT`、`UNIQUE KEY`、表/字段 `COMMENT`、`ON UPDATE` 和哈希分区。
- PostgreSQL：schema、`SERIAL`/`BIGSERIAL`、数组、类型转换默认值、`COMMENT ON` 及跨 schema 外键。
- SQL Server：方括号标识符、`IDENTITY(seed, increment)`、命名默认约束、`DATETIME2` 及跨 schema 外键。
- Oracle：`NUMBER`、`VARCHAR2(... CHAR)`、`GENERATED BY DEFAULT AS IDENTITY`、`SYSTIMESTAMP` 和 `COMMENT ON`。
- SQLite：双引号标识符、`INTEGER PRIMARY KEY AUTOINCREMENT`、唯一约束、默认值和自引用外键。
- Hudi（Spark SQL）：`USING HUDI`、`PARTITIONED BY`、`TBLPROPERTIES` 以及嵌套 `ARRAY`/`MAP`/`STRUCT` 字段类型。
- Hive：表/字段注释、`PARTITIONED BY`、`STORED AS`、`TBLPROPERTIES` 和复杂字段类型。
- HBase：兼容 Phoenix SQL 的列族限定字段、复合主键、`UNSIGNED_TIMESTAMP`、`SALT_BUCKETS` 等常见建表语法；HBase Shell 的 `create` 命令不是 SQL，不在解析范围内。
- MaxCompute（MC）：表/字段注释、复杂字段类型、`PARTITIONED BY` 和 `LIFECYCLE`；`mc` 与 `maxcompute` 均可作为方言参数。

以上方言均支持字段级及表级主键、唯一键和外键。解析器面向常见 `CREATE TABLE` 字段清单，不执行 SQL，也不展开存储过程、触发器、索引选项或每个分区的边界定义。
