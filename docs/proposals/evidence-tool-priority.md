# Evidence Tool 优先级与范围决策材料

- **编制日期**：2026-09-20
- **阶段**：第一阶段，仅做能力盘点、优先级和范围决策；不扩大实现。
- **变更边界**：本阶段不修改 Core、GUI、`pyproject.toml`、插件业务代码、测试或发行脚本。

## 1. 执行摘要

当前 `evidence-tool` 不是空白能力，而是一个 **CURRENT/PARTIAL 的兼容工作流**。`evidence.build` 已能在一次 TestBox 任务内完成：Excel 测试用例识别、待执行项筛选、截图关联、Word 报告生成、Excel 执行状态回写，并生成 `evidence-index.json` 作为追踪索引。它有批处理模式，也有基于 PySide6 的交互截图/标注模式。

但它还不应被视为已完成的产品线：

1. 可用性依赖 `openpyxl`、`Pillow`、`python-docx`；交互模式还依赖 PySide6、桌面环境和屏幕录制权限。
2. 本工作区的 Evidence 完整集成测试因可选依赖未安装而跳过，当前无法宣称完整业务闭环已经验证。
3. 浏览器自动化、最终报告格式、macOS/Windows 支持等级，以及是否把 Evidence 提升为下一阶段主线，仍是 `NEEDS_CONFIRMATION`。

### 默认优先级建议

- **P0：兼容维护与发布阻断项**。保留当前能力，补齐真实依赖/安装验证、错误诊断和声明平台的基本验证；不新增浏览器自动化、不改变 Core/Host 协议、不扩展报告格式。
- **P1：证据工作流产品化**。只有在确认 Evidence 是下一阶段重点后，才完善 Excel 模板适配、批处理/交互可靠性、部分完成与恢复、报告追溯和跨平台桌面验证。
- **P2：范围扩展**。浏览器自动化、更多采集源、PDF/HTML/项目级汇总、外部系统同步和跨平台完整体验，均暂不进入当前基线。

**总建议**：Evidence Tool 当前定为 **P1（有条件进入下一阶段主线）**；P0 仅做兼容维护和发布质量门槛。若业务确认“测试证据是下一阶段核心场景”，再把 P1 提升为产品线 P0，并重新确认平台、报告和自动化范围。

### 2.1 Manifest、Schema 与执行契约

当前 manifest：

- 名称 `evidence-tool`，版本 `2.0.0`
- 命令 `evidence.build`
- Core 兼容范围 `>=1.0,<2.0`
- `concurrency: false`、`network: false`、`filesystem: output-only`
- 入口 `src.main:Plugin`

Schema 参数：

- `input`：必填，支持 `.xlsx`/`.xlsm`
- `interactive`：默认 `true`
- `screenshots`：批处理截图列表
- `row_indexes`：截图对应的 Excel 行号
- `existing_reports`：已有 Word 报告，用于继续追加
- `column_mapping`：业务角色到表头的映射
- `status`、`update_excel`、`include_unmatched`
- `image_width_inches`

关键行为：

- 交互模式不能接收 `screenshots`；批处理模式必须显式接收 `screenshots`。
- `row_indexes` 与截图必须一一对应且不能重复；行不存在时失败。
- 未提供 `row_indexes` 时按待执行项顺序关联；截图数量不一致默认失败，除非明确允许未匹配项。
- 没有待执行项时写出索引并返回成功摘要。

### 2.2 已实现能力

**Excel 识别与筛选**

- 在默认前 15 行内识别表头。
- 使用中英文别名、归一化和简单模糊匹配建议列映射。
- 校验必需角色：测试名称、验证点、测试结果。
- 支持基础用例和步骤式用例。
- 继承测试名称、验证点的纵向合并单元格。
- 跳过 `已执行`、`通过`、`完成`、`成功`、`passed`、`done` 等状态。
- 输出列样例、建议映射、映射理由和缺少角色信息。

**截图与报告**

- 批处理可按顺序或显式行号关联截图。
- Pillow 校验图片可读取。
- `include_unmatched` 支持部分完成，并在索引中记录缺失项。
- 每个测试名称生成一个 DOCX；文件名清理后追加短哈希，避免非法字符导致覆盖。
- 写入验证点、步骤信息和截图。
- 追加已有报告时，对同名验证点做简单去重，但会追加新的截图。
- 将执行状态写回 Excel，并输出任务内的 Excel 副本。

**任务追踪**

- Runtime 负责输入暂存、任务工作区、结果和报告。
- 插件输出 `evidence-index.json`，记录输入文件、表头、映射、模式、已保存项、报告、Excel 是否更新、未匹配项。
- Runtime 另行生成标准 `manifest.json`、`result.json` 和 `report.md`。

**交互模式**

- PySide6 列映射确认对话框。
- 逐条执行面板和进度显示。
- F8 触发截图；截图时隐藏执行面板，延迟后调用 Qt 主屏幕 `grabWindow(0)`。
- 标注工具包括矩形、椭圆、荧光笔、画笔、文字、裁剪、撤销和缩放。
- 保存后立即写入截图、Word 和 Excel 状态；支持跳过、提前结束。

## 3. 已知缺口

### 3.1 测试、依赖和发布

1. 本次在隔离工作区执行：

   ```text
   python3 -m unittest discover -s tests -v
   ```

   结果为 **84 个测试，0 个失败，5 个跳过**。跳过的是依赖 `openpyxl`、`Pillow`、`python-docx` 的 Evidence 集成测试。因此 Core/无依赖路径通过，但完整 Evidence 闭环尚未被本环境验证。

2. Evidence 没有独立的 `plugins/evidence-tool/tests/`；测试集中在 `tests/test_integration.py`。

3. `pyproject.toml` 将 `openpyxl`、`python-docx`、`Pillow` 放在默认依赖中，而插件自身也有 `requirements.txt`。这使 Core 默认依赖、插件独立安装和发行包的边界不清，应交给依赖/发行任务决策；本阶段不修改。

4. 交互截图、窗口隐藏、标注保存、屏幕权限和多屏行为没有可重复的自动化验证。

### 3.2 输入兼容性

- 仅支持 `.xlsx`/`.xlsm`，不支持 `.xls`。
- 只处理 active worksheet，没有工作表选择、跨工作簿或批量工作表入口。
- 表头扫描默认为 15 行；多级表头、复杂模板和多个候选表头未形成稳定承诺。
- 映射依赖别名和简单模糊匹配，没有映射模板保存/复用，也没有完整的冲突解释机制。
- 执行状态词集合固定，不同团队的失败、跳过、不适用等语义未形成契约。
- `.xlsm` 的宏保留、外部链接、公式重算、保护工作表、文件锁定和 Excel 版本差异未单独验收。
- 行号映射虽能减少顺序漂移，但没有输入内容快照/哈希级防错确认；任务前后修改 Excel 时仍可能指向不同内容。

### 3.3 输出与报告

- 当前输出是“按测试名称拆分的 DOCX + 执行后的 Excel 副本 + 截图 + `evidence-index.json`”，不是项目级汇总报告。
- 没有已确认的 PDF、HTML、Markdown、单一汇总 DOCX 或打印模板。
- Evidence 报告自身没有统一的执行人、执行时间、环境、版本、输入/截图哈希、失败原因和审阅元数据契约；Runtime 的 manifest/result 只能部分补足。
- 追加报告的去重只识别 `验证点：` 段落，不是通用的报告版本管理或幂等导入机制。
- 没有长图、超大分辨率、方向、压缩、分页和最终文档大小的稳定性承诺。
- 报告命名虽避免覆盖，但无用户可配置模板和跨任务归档策略。

### 3.4 交互、权限和恢复

- 默认交互模式不适合 CI、服务器、远程终端和无屏幕录制权限环境；批处理是现有替代路径。
- Core/Host 当前是一次 JSON 请求/一次响应，没有通用实时进度、日志流或 Core 级取消契约。插件内的 UI 不能等同于 Runtime 的任务可观测性。
- 跳过和提前结束存在，但没有正式断点续跑；中断后报告、Excel 和再次运行之间的幂等语义未定义。
- 报告写入成功但 Excel 回写失败、Excel 保存成功但报告失败、窗口关闭或进程中断时的恢复规则未定义。
- 使用 Qt 主屏幕捕获，未验证多显示器、DPI、虚拟桌面、非主屏窗口、主题和焦点行为。
- `interactive.py` 依赖 PySide6，但插件 `requirements.txt` 未声明 PySide6；项目 `desktop` extra 的覆盖关系未确认。

## 4. 依赖与跨平台风险

| 依赖 | 用途 | 主要风险 |
| --- | --- | --- |
| `openpyxl` | 读取/识别/回写 `.xlsx`/`.xlsm` | 宏、公式、锁定文件、版本兼容性 |
| `Pillow` | 验证截图 | 格式、超大图片内存和解码异常 |
| `python-docx` | 创建/追加 DOCX | Word 兼容性、分页、图片尺寸、文档损坏/锁定 |
| `PySide6` | 映射、截图、标注 | 未在插件 requirements 声明；需要桌面、Qt 平台插件和权限 |

没有发现 Evidence Tool 使用网络库、浏览器驱动、外部命令或远程服务；manifest 声明无网络。

### macOS

- 屏幕录制权限是硬前置；拒绝时必须给出批处理替代路径。
- Retina 高 DPI 的物理像素/逻辑坐标可能影响标注和 Word 尺寸。
- Qt 窗口焦点、全屏、多桌面、多显示器行为未验证。
- Office 文件锁定和同步目录占用未定义处理。

### Windows

- PyInstaller `onedir` 需要验证 Evidence 依赖、Qt 平台插件和资源是否完整收集；构建成功不等于交互运行成功。
- DPI、多屏、窗口置顶、焦点切换、路径长度、杀毒软件扫描临时文件和 Office 锁定都可能影响流程。
- 安装程序内置插件和独立 Evidence ZIP 的依赖策略需保持一致。

### 无桌面/CI

- 批处理是现有唯一适合无桌面环境的路径，但仍依赖三个文档/图片库。
- 无 display 时交互模式会失败；当前没有统一的“依赖缺失/显示服务缺失/权限拒绝/文件锁定”诊断矩阵。

## 5. 浏览器自动化范围

### 当前事实

当前没有浏览器自动化：没有 WebDriver、Playwright、Selenium、CDP 或外部命令；截图来自用户提供的图片或 Qt 主屏幕捕获；不读取网页、不登录系统、不执行测试步骤。

### 默认建议：P2

浏览器自动化默认放入 **P2**，不进入当前 `evidence.build` 基线。它会引入浏览器版本、驱动/二进制、登录态、MFA、弹窗、下载、跨域、网络稳定性、凭据处理、脱敏和取消/重试等新问题，并会把产品从“整理已有截图”扩展成“执行/采集 Web 测试”。

若业务确实需要，建议做成独立能力或独立插件，而不是隐式塞入 `evidence.build`，并声明网络、浏览器和凭据能力。只有在以下事项确认后，才考虑从 P2 提升 P1：

- 目标是执行并采集 Web 测试，而不只是整理现有截图。
- 允许网络访问并定义域名、代理、证书和离线行为。
- 定义登录、凭据、MFA、会话和敏感数据处理。
- 定义浏览器、系统、分辨率、下载、弹窗支持矩阵。
- 定义超时、取消、重试、失败截图和审计日志。
- 明确与现有 `evidence.build` 的输入输出关系，禁止插件直接互相导入。

## 6. 最终报告范围建议

### P0 保持现状

可承诺：

- 每个测试名称一个 DOCX 证据报告。
- 有证据且启用回写时，一份执行后的 Excel 副本。
- 交互模式的截图/标注图作为任务输出。
- `evidence-index.json`，包含映射、已保存项、未匹配项和报告列表。
- Runtime 标准 `manifest.json`、`result.json`、`report.md`。

不承诺：项目级统一报告、PDF/HTML、浏览器步骤日志、自动测试结论、在线审阅或跨任务数据库。

### P1 产品化

在确认成为主线后，可增加：

- 项目级摘要：总数、完成、未完成、跳过、失败/异常、证据覆盖率。
- 稳定报告元数据：任务 ID、输入名/哈希、版本、生成时间、状态和输出索引。
- 明确部分完成、提前结束、缺图、失败和重跑语义。
- Excel 行、截图、验证点、报告段落之间的双向追溯。
- 先选择一种汇总格式（单一 DOCX 或 Markdown/HTML）落地，不同时实现多种格式。

### P2 扩展

PDF/HTML 正式发布版、多工作簿/多工作表合并、浏览器视频/HAR/网络证据、跨任务项目归档和外部系统同步均列为 P2，除非另行确认。

## 7. P0/P1/P2 项目与验收条件

### P0：兼容维护、安装和发布质量

## 9. 决策顺序与阶段结论

建议先确认 NC-01/02/03（优先级与平台），再确认 NC-08/09（最终报告），再确认 NC-04/05/06（输入、状态、恢复），最后确认 NC-07/11/12/13（自动化、依赖、权限）。

阶段结论：

- 当前能力应保留，不应在范围未确认前删除或大规模重写。

- 浏览器自动化默认属于 P2；若需要自动执行 Web 测试，应作为独立范围评审。
- 当前生成 DOCX 不等于 DOCX 已被确认是最终产品标准。
- 本阶段只新增本决策材料，不修改 Core、GUI、`pyproject.toml`、插件业务代码或测试。
