# TestBox 需求基线

> 本文件只描述产品要做什么，不描述具体代码实现。
>
> 状态：基线重构完成（2026-08-25）。当前代码是部分可运行实现，不能视为全部需求已经交付。

## 1. 项目目标

TestBox 是一个面向测试工程师的本地测试效能工具箱。它要把分散的测试辅助能力收敛到统一入口，使用户可以：

1. 选择一个测试工具或插件。
2. 填写参数并执行任务。
3. 获得可复现、可追溯的输出文件。
4. 在本地查看任务状态、日志、结果和报告。
5. 在不修改 Core 的情况下增加新的工具插件。

## 2. 产品定位

TestBox 是本地运行、插件化、面向测试工作的 CLI 与桌面 GUI 工具。它不是云端平台、团队协作平台、远程执行平台，也不要求引入服务端或复杂基础设施。

## 3. 目标用户

- 测试工程师
- 自动化测试人员
- 测试开发人员
- 需要临时测试数据、SQL 字段清单或测试证据的研发/测试人员

## 4. 核心使用场景

### 4.1 生成测试数据

用户根据数量、格式、随机种子、模板或字段规则生成模拟数据，用于接口、数据库或 UI 测试。生成结果必须可复现，且不得伪装成真实身份材料。导出文件名使用当前任务 ID 作为文件名主体。

### 4.2 解析 SQL 字段

用户提供 SQL DDL 文件，获得字段、类型、长度/精度、注释、约束、分区等字段清单。解析器只解析文本，不连接数据库、不执行 SQL。无法识别的内容必须可见地形成警告或失败原因。每次任务的字段清单文件使用任务 ID 作为文件名主体，便于追踪和作为下游插件输入。

### 4.3 根据字段清单生成 SELECT

用户可将 `sql.parse` 任务生成的 JSON、CSV 或 XLSX 字段清单交给下游插件，按表分组生成 SELECT 语句。该插件只生成文本，不连接数据库、不执行 SQL；输出文件同样使用下游任务 ID 作为文件名主体。

### 4.4 生成测试证据

用户可将测试用例与截图整理为可追溯证据报告。`evidence.build` 在一次任务内完成 Excel 表头识别、待执行项筛选、截图关联、Word 报告生成和 Excel 状态回写，并支持批处理与桌面交互模式。

### 4.5 管理任务与插件

用户可以查看可用命令、运行任务、查看历史任务、打开任务工作区、清理过期工作区，并对插件包进行校验、安装、覆盖安装和卸载。

## 5. 功能范围

### 5.1 Core 与 CLI

- 发现本地插件并校验清单。
- 列出可用命令和不可用插件的原因。
- 根据命令 Schema 校验参数。
- 创建独立任务工作区。
- 执行插件并保存日志、结果、报告和输出文件。
- 返回稳定的成功、失败、取消状态和进程退出码。
- 查看任务详情。
- 清理指定日期以前的任务工作区。
- 打包、校验、安装、覆盖安装和卸载插件。

### 5.2 Data Generator

命令：`data.mock`。

最低能力：

- 生成模拟个人信息、手机号等测试数据。
- 支持随机种子。
- 支持 JSON、CSV、XLSX 等已实现或确认的输出格式。
- 支持规则集、SQL DDL、Excel 字段清单和金融模板等规则化输入（以插件 Schema 为准）。
- 唯一性必须显式声明，只在当前任务内保证唯一；容量不足时失败，不静默输出重复值。
- 证件/身份类内容必须明确标识为测试数据，不能用于真实认证。

### 5.3 SQL Parser

命令：`sql.parse`。

最低能力：

- 解析常见 `CREATE TABLE` 定义。
- 提取字段、类型、长度/精度、注释、主键、唯一、外键、自增、默认值和分区等信息（取决于输入方言）。
- 支持仓库测试覆盖的 MySQL、PostgreSQL、SQL Server、Oracle、SQLite 及已实现的相关 DDL 变体。
- 输出 JSON/CSV/XLSX 等插件 Schema 支持的字段清单。
- 支持宽松警告与严格失败两种使用方式。
- 不执行用户提供的 SQL。

### 5.4 SQL Select Generator

命令：`sql.select`。

最低能力：

- 消费 `sql.parse` 生成的 JSON、CSV、XLSX 字段清单。
- 按 `table` 分组并保持字段顺序生成 SELECT 语句。
- 支持常见 SQL 方言的标识符引用。
- 不执行 SQL，不连接数据库。

### 5.5 Evidence Tool

当前实现包含：

- 从 Excel 测试用例识别待执行项。
- 关联截图与检查点。
- 生成 Word/Excel 等证据输出。

这部分保留为现有能力，但扩展优先级、浏览器自动化范围和最终报告格式为 `NEEDS_CONFIRMATION`。

### 5.6 GUI

GUI 必须是 Core/Runtime 的可视化入口，而不是第二套业务实现。至少需要支持：

- 浏览工具和命令。
- 根据 Schema 填写参数。
- 选择文件输入。
- 执行、取消或等待任务完成。
- 查看任务状态、日志摘要、结果、警告、输出文件和报告。
- 查看任务历史和工作区。
- 查看插件状态、版本、能力和诊断信息。

当前 GUI 仅作为现状参考，不作为视觉资产保护对象，后续允许整体重做。

## 6. 用户主流程

1. 查看工具/插件列表。
2. 选择命令。
3. 查看命令说明和参数要求。
4. 填写参数并进行本地校验。
5. 启动任务。
6. 获取任务 ID，并显示任务状态。
7. 查看结果、警告、日志和输出路径。
8. 需要时打开或导出任务产物。
9. 按生命周期策略清理历史工作区。

CLI 与 GUI 必须使用相同的 Runtime、插件清单、Schema 和结果模型。

## 7. 业务规则与约束

- 插件之间不得直接调用或共享内部实现；跨插件能力必须经 Core 协调。
- 插件只能通过稳定 SDK 使用任务目录、配置、日志和输出能力。
- 输入文件在任务边界内处理，并记录来源与哈希（当前代码对 Schema 声明的文件输入进行暂存）。
- 输出文件必须位于任务 `output/` 内，结果只能声明相对路径。
- 参数、任务清单、日志和报告不得泄露密码、令牌、连接串等敏感值。
- SQL、脚本和未知插件代码不应被当作可信输入执行；当前 V1 插件仍属于本地可信插件，清单校验不等于操作系统安全沙箱。
- 不提供云端同步、多人协作、远程执行或插件市场作为当前目标。

## 8. 非功能要求

- 本地 CLI 冷启动目标为 3 秒以内；实际基准需在目标机器上测量。
- 单次生成 100,000 条测试数据是目标规模，不能据此承诺所有插件都达到相同吞吐量。
- 相同插件版本、参数、输入和随机种子应产生可复现结果。
- 失败任务必须保留足以诊断的结构化错误和任务工作区。
- 插件故障、超时或进程异常不得使 Core 进程整体崩溃。
- 输出和日志大小必须有上限或可配置限制。

## 9. 当前版本基线

### 已在当前代码中观察到

- Python 包、CLI 入口和可选 PySide6 GUI。
- 本地插件发现与 `manifest.yaml` 校验。
- Plugin Host 子进程执行。
- 任务工作区、SQLite 任务历史、结果 JSON 和 Markdown 报告。
- `data.mock`、`sql.parse`、`sql.select`、`evidence.build` 命令。
- 插件包打包、安装、覆盖安装和卸载。
- 集成测试覆盖 Core、Data Generator、SQL Parser 和部分 Evidence Tool 流程。

### 当前最低交付建议

优先稳定以下闭环，再扩大功能：

1. Core/CLI 插件发现。
2. `data.mock` 可复现生成。
3. `sql.parse` 字段清单输出。
4. `sql.select` 消费字段清单并生成 SELECT。
5. 任务追踪、结果和工作区。
5. 可重做的 GUI 基础入口。

Evidence Tool、Excel Tool、Env Check、AI 插件、插件市场等作为后续能力，不在本轮基线中扩张。

## 9.1 Windows 发布与自动版本

- Windows 主程序使用 PyInstaller `onedir`，GitHub Release 必须分别提供 CLI 的 `TestBox-CLI-Install-vX.Y.Z.exe`、`TestBox-CLI-Setup-vX.Y.Z.exe` 和 GUI 的 `TestBox-GUI-Install-vX.Y.Z.exe`、`TestBox-GUI-Setup-vX.Y.Z.exe`，不能只提供绿色包或只提供增量包。
- CLI 与 GUI 必须使用独立安装目录、独立更新载荷、独立更新清单和独立 updater；更新清单必须带组件身份，跨组件更新必须被拒绝。CLI 不得打入 Qt 桌面依赖；GUI 只收集实际所需 Qt 模块，以尽可能降低安装包大小。
- 增量安装程序内部使用版本化更新载荷，要求从对应产品的上一正式版本升级；CLI/GUI 的更新清单和增量 ZIP 都作为技术载荷随 Release 发布。旧版 CLI+GUI 合包用户通过相应完整安装器迁移。
- 每次推送到 `main` 或 `master` 都由 GitHub Actions 创建正式版本，版本号以最新 `vX.Y.Z` 标签为基准自动增加补丁号 `0.0.1`，并同步 Python 包、运行时版本和四个 Windows 安装程序的版本。
- Pull Request 只执行测试和构建验证，不创建版本提交、标签或正式 Release。

## 10. Out of Scope

- 云端数据库、云端任务队列和远程插件执行。
- 多用户账号、登录、团队权限和在线协作。
- Kubernetes、微服务、消息队列等基础设施。
- 任意 SQL 执行、数据库连接代理或生产数据同步。
- 真实个人信息、真实身份证件或可通过真实认证的材料生成。
- 本轮直接重写业务代码或实现新的 GUI。

## 11. 验收标准

| 类别 | 验收标准 |
| --- | --- |
| 发现 | 无效插件不能阻塞有效插件；用户能看到无效原因。 |
| 执行 | 合法命令能接收 Schema 参数并返回结构化成功/失败结果。 |
| 可追溯 | 每次任务有唯一 ID、工作区、脱敏参数、结果、报告和输出路径。 |
| 可复现 | 相同版本、输入、参数和 seed 的生成任务结果一致。 |
| 安全 | 不把密钥写入日志/历史；身份类模拟产物有明确测试标识。 |
| 失败处理 | 参数错误、输入错误、插件异常、超时都能给出可理解的错误摘要。 |
| GUI | GUI 显示的任务状态和结果必须来自同一 Runtime，而不是复制业务逻辑。 |
| 回归 | Core、Data Generator、SQL Parser 的现有自动化测试持续通过。 |

## 13. 状态定义

- `COMMITTED`：产品方向和验收要求已纳入基线。
- `IMPLEMENTED`：当前代码中已观察到对应能力。
- `PARTIAL`：有实现或测试，但未达到完整目标。
- `NEEDS_CONFIRMATION`：需要产品或架构决策后才能进入正式实现。

本文件中的“当前版本基线”同时区分产品目标和代码现状，不能将 `IMPLEMENTED` 自动理解为最终产品已验收。

## 11. 多格式比对、结构分析与数据质量（2026-10-07 确认范围）

用户确认增加 P1 数据比对、P2 结构比对、P3 数据质量；导入文件/SQL 后必须能预览解析结果、调整换行/记录分隔符、列分隔符等配置并重新预览。Windows 原生安装、增量更新与回滚流水线验收本阶段跳过，仍为未验证。

### 11.1 公共导入与预览

- CLI 与 GUI 同一套解析逻辑；预览为真实可追溯任务，不在 GUI 复制解析算法。预览展示样本及来源位置，注明总行数、样本截断、解析警告；不得据样本认定全量一致。
- 两侧输入独立选择格式与配置，支持跨格式比较；首批支持 XLSX/XLSM、CSV/TSV、分隔 TXT、JSON 对象/对象数组、JSONL，以及 SQL 文本载体。
- 文本配置支持编码、列分隔符、记录分隔符、引用/转义符、表头与数据起始位置；Excel 支持 Sheet 与表头/数据起始行；JSON 支持点分数据路径。不把分隔符配置强行应用于 Excel/JSON。
- CSV 引号字段中的分隔符、换行保持为字段内容；TXT 可显式配置多字符列与记录分隔符；自动识别不确定必须提示，显式配置优先。
- 默认保持前导零、空白、大小写与类型；显式标准化支持列映射、trim、casefold、指定空值标记和基础类型转换。缺失字段、null、空字符串不得默认合并。类型转换失败/列映射冲突报错，不静默填空或丢行。
- 不修改原文件、不计算公式、不执行宏/SQL；重复字段、无效引用、字段数量不齐、非有限JSON值等应失败。输入、解析深度、行列/单元格及报告明细有资源限制；超限不得假装完整。

### 11.2 P1 data.compare

- 两份数据按位置、单/组合主键或无序多重集合对齐；无序模式保留重复次数，主键模式重复/空/缺失键报错。
- 支持独立标准化、忽略列、数值绝对/相对容差；严格类型优先，不把布尔值视为整数。
- 输出列差异、左/右独有记录、字段变化及来源定位；数据不一致与任务执行失败分离。明细截断时仍核对全部数据并报告总差异数与截断状态。

### 11.3 P2 sql.diff / sql.preview

- 输入是SQL文本或结构清单，可由 SQL/TXT、Excel、CSV、JSON等文件承载；SQL载体选择列，结构清单有独立模式。
- 首批识别有测试覆盖的常见 CREATE TABLE、显式列 SELECT 和显式列 INSERT。支持解析预览；SQL内换行不意味着语句结束，字符串/注释内分隔符不可直接拆分。
- 区分声明、推断、未知和不支持；SELECT/INSERT不能凭空还原类型、约束和完整表结构。SELECT *、缺少INSERT列清单、复杂语法、没有基线的ALTER不允许当成完整一致。
- 报告 equal/different/inconclusive 与信息完整度；有已知差异可报告different，信息不足不得报告equal。不得执行SQL或宣称完整查询语义等价。

### 11.4 P3 data.check

- 复用导入/标准化，支持必填、单/组合唯一、类型、枚举、数值范围、长度、跨字段比较、行数规则。
- 声明式配置，未知规则/非法参数明确失败，不执行任意表达式；错误与警告分级。
- 报告全量计数、规则汇总、源位置与明细截断；检查失败与插件执行失败分离，不自动清洗或回写。

### 11.5 验收与后续范围

- 跨格式一致、引用字段内换行/分隔符、前导零/缺失/null区别、重复键/重复次数、容差边界、全量统计与截断、来源不变、预览修改后失效/重跑、未知SQL不假报一致均需回归。
- 固定宽TXT、旧XLS、XML、目录/多Sheet批量、任意日期/布尔映射、完整CTE/JOIN/UNION/ALTER及跨数据库类型兼容分析是后续增强，不因本节列出就当作已交付。
- 若复杂SQL需要新增解析依赖，先说明名称/版本/必要性与兼容影响，再实施；本阶段复用已有依赖。
